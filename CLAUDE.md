# CLAUDE.md — сайт RUE DE MIRÓ

Подробное описание сайта, деплоя, DNS и SSL — в [README.md](README.md). Здесь — что нужно знать Claude Code, чтобы обновлять и проверять сайт. Пользователь общается по-русски.

## Коротко

- Сайт: https://ruedemiro.com — статические страницы `*.html` из Claude Design (`index.html`, `assort.html`, `core.html` …, рантайм `js/dc-lite.js`), сборки нет. До 02.10.2026 были страницы `*.dc.html` — их больше нет, редиректы со старых адресов пользователь делать не захотел.
- Деплой: **push в `main`** → GitHub Actions (`.github/workflows/deploy.yml`) делает бэкап на сервере, заливает файлы rsync'ом и сверяет md5 прямо с IP хостинга. Больше ничего делать не нужно. Результат: `gh run list -L 1`, `gh run watch <id>`.
- Хостинг: RU-CENTER (nic.ru), SSH-алиас `rdm` (см. «Первая настройка»), папка сайта `~/ruedemiro.com/docs`, IP веб-сервера `91.189.114.4`.
- DNS: DNS-хостинг RU-CENTER (`ns3-l2/ns4-l2/ns8-l2/ns4-cloud/ns8-cloud.nic.ru`). Почта salut@ruedemiro.com — Яндекс 360.

## Обновление сайта новой выгрузкой из Claude Design

1. Распаковать zip **только через `ditto`** — `unzip` портит кириллические имена файлов:
   `ditto -x -k "<архив>.zip" <временная папка>`
2. Посмотреть, что изменилось (`diff -rq`), скопировать файлы выгрузки поверх репозитория. Файлы, которых нет в выгрузке (`README.md`, `CLAUDE.md`, `.github/`, `.gitignore`, `.nojekyll`), не трогать. Если в выгрузке есть `.htaccess` — в репозиторий не класть (rsync его не заливает), а сравнить с серверным `~/ruedemiro.com/docs/.htaccess` и переносить изменения туда вручную, сохраняя правило для `.well-known/acme-challenge/` и редирект через `X-Forwarded-Proto`. Файлы, которые из выгрузки пропали, удалить из репозитория только после вопроса пользователю.
3. Не переименовывать `*.html` и не менять пути внутри страниц — страницы ссылаются друг на друга по именам.
4. `git add -A && git commit -m "…" && git push`, дождаться зелёного деплоя, показать пользователю результат.

## Проверка сайта

- Проверять по IP хостинга, а не через DNS компьютера: `curl -s -o /dev/null -w '%{http_code}\n' --resolve ruedemiro.com:443:91.189.114.4 https://ruedemiro.com/`
- DNS проверять у самих серверов nic.ru: `dig +short ruedemiro.com A @ns3-l2.nic.ru`. Домашний роутер или провайдер могут часами помнить старый/пустой ответ — тогда сайт «не открывается» только у пользователя дома; лечится перезагрузкой роутера или DNS `77.88.8.8` / `1.1.1.1`.
- 404 в консоли на адреса вида `{{ res.href }}` — заготовки шаблона, это нормально.
- Редиректы http→https, www→без www и адреса без `.html` (`/core` → `core.html`, а `core.html` и `/core/` — 301 на `/core`) а также страница `404.html` и 301-редиректы со старых адресов сайта на Tilda (`/offer`, `/blog`, `/tproduct/…` и т. п.) работают через `~/ruedemiro.com/docs/.htaccess` на сервере (в репозитории его нет, rsync его не трогает).

## Чего не делать

- **Не оптимизировать/не пережимать картинки без согласования.** WebP-сжатие (1600 px, качество 80) уже пробовали — пользователь сказал, что картинки стали пиксельными, всё откатили. Любую новую попытку сначала показать на тестовой странице и получить «да».
- Не вводить пароли за пользователя (хостинг, панель, GitHub). Если нужен пароль — дать команду, которую пользователь выполнит сам в Терминале.
- Не делать много неудачных SSH-входов подряд: хостинг блокирует IP.
- Не трогать `.htaccess` и `.well-known/` на сервере без нужды. Если правите `.htaccess`: HTTPS на nic.ru завершается на прокси, проверять надо `%{HTTP:X-Forwarded-Proto}`, а не `%{HTTPS}`.
- `.htaccess` действует только на HTML: картинки, JS, CSS, шрифты отдаёт nginx хостинга напрямую (gzip/кэш для них — только в панели).
- DNS-записи меняет пользователь в панели RU-CENTER; после правки обязательно «Выгрузить зону», в CNAME/MX — точка в конце (`ruedemiro.com.`).

## SSL-сертификат

Let's Encrypt через `~/.acme.sh` на сервере (cron на хостинге нет — продление вручную). Текущий действует до **31.12.2026**; продлевать в начале декабря и далее каждые ~60 дней. Команды — в README, раздел «HTTPS». После продления пользователь сам загружает файлы из `~/ssl` в панель хостинга. Проверка после загрузки:
`echo | openssl s_client -connect 91.189.114.4:443 -servername ruedemiro.com 2>/dev/null | openssl x509 -noout -enddate`

## Первая настройка на новом компьютере

1. `gh auth status` — должен быть вход в GitHub-аккаунт, где лежит репозиторий. Клонировать: `gh repo clone <владелец>/ruedemiro-site`.
2. SSH к хостингу (нужен для SSL и бэкапов, не для обычного деплоя):
   - создать ключ: `ssh-keygen -t ed25519 -N "" -C "ruedemiro-<имя>" -f ~/.ssh/ruedemiro_nic`
   - добавить в `~/.ssh/config`:
     ```
     Host rdm
       HostName ssh.<логин хостинга>.nichost.ru
       User <логин хостинга>
       IdentityFile ~/.ssh/ruedemiro_nic
       IdentitiesOnly yes
       HostKeyAlgorithms +ssh-rsa
       PubkeyAcceptedAlgorithms +ssh-rsa
     ```
   - публичный ключ (`~/.ssh/ruedemiro_nic.pub`) должен попасть в `~/.ssh/authorized_keys` на сервере: либо его добавит тот, у кого доступ уже есть, либо пользователь сам выполнит в Терминале (спросит пароль хостинга):
     `cat ~/.ssh/ruedemiro_nic.pub | ssh -o PubkeyAuthentication=no -o HostKeyAlgorithms=+ssh-rsa <логин>@ssh.<логин>.nichost.ru 'cat >> ~/.ssh/authorized_keys'`
   - проверить: `ssh rdm 'ls ~/ruedemiro.com/docs | head'`
   Логин хостинга в репозиторий не записывать (репозиторий публичный) — он есть в секрете `SFTP_USER` и в панели RU-CENTER.
